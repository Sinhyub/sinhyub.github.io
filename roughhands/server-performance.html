[기술개발] 안정성과 성능을 만족하는 게임 서버 설계 (1) : 높은 성능 편

2016-04-06 · RoughHands 게임 제작기

크루세이더스 듀얼은 다수의 사용자가 '실시간'으로 즐기는 '온라인'게임이기에, 성능과 안정성 모두 만족시키고자 하였다. 먼저 본 편은, 높은 성능을 만족시키기 위한 고민과 선택의 이야기이다.

성능을 위해 다음과 같은 선택이 있었다.

  • 멀티스레드를 적극적으로 사용 — 다수의 사용자가 실시간으로 상호작용하기 위해서는 공유자원에 대한 접근이 쉬워야 한다. 이를 위해, 프로세스 메모리를 사용하여 공유자원을 관리하는 것을 선택했다. 따라서 하나의 프로세스로 구성된 어플리케이션의 성능을 끌어올릴 방법이 필요했고, 멀티스레드를 적극적으로 사용하였다.
  • 비동기 처리(Asynchronous)를 적극적으로 사용 — 다수의 사용자 요청을 실시간(짧은 응답시간)으로 처리하기 위해서, 비동기 처리를 적극적으로 사용한다. 해당하는 처리는 네트워크 입출력, 데이터베이스 요청 처리, 로그 처리(디스크 입출력)가 있다.

멀티스레드의 적극적인 사용

멀티스레드는 하나의 프로세스가 여러개의 물리적인 CPU 코어를 사용할 수 있게하여 성능을 향상시킬 수 있지만, 동기화라는 새로운 고민을 던져준다. 뿐만 아니라 운영체제가 코어에 배정할 스레드를 관리하며 발생하는 오버헤드가 있다.

동기화 비용 최소화

멀티스레드를 적극적으로 사용했던 MMORPG 라이브 서비스 경험을 돌아보면, 응답 지연을 발생시키는 주요 원인은 공유자원 접근시, 상호배제로 인해 요청을 처리하던 스레드가 봉쇄되는 것이었다. 이번 프로젝트에서는 이런 동기화 비용(상호 배제로 인한 봉쇄)를 줄이는 것을 설계시부터 고려했고, 다수의 스레드에서 빈번하게 접근하게 될 공유 컨테이너(자료구조)에는 적절히 락-프리-컨테이너(Lock Free Container)를 사용하고, 컨텐츠 레벨에서 락(Lock)을 최소화 할 수 있는 기반을 설계했다.

스레드 컨트롤러를 활용한 동적인 스레드 운용

다양한 테스크(Task)를 처리하는 게임 서버에서, 병목이 되는 테스크를 미리 예측하기는 어렵다. 이로 인해 스레드의 생성시 테스크가 정적으로 바인딩 되는 OS 기본 매커니즘에서는 병목이 되는 태스크에 대응하는 것도 어렵다. 스레드 컨트롤러(ThreadController)를 통한 동적인 스레드 운용은 이를 해결할 수 있는 좋은 방법이었다. 뿐만아니라, 물리적 코어 수에 최적화된 숫자의 스레드를 운용할 수 있게 됨으로써 컨텍스트 스위칭 비용도 줄일 수 있다.

비동기 처리의 적극적인 사용

비동기 처리는 보유한 하드웨어자원을 최대한 활용하는 것을 목적으로 한다. CPU연산보다 더 오랜 시간이 소요되는 작업의 '요청'과 '수행', '완료 처리'를 나누어 비동기적으로 처리함으로써, 모든 자원을 더 효율적으로 사용할 수 있게 된다.

비동기 네트워크 입출력

게임 서버에서 네트워크 입출력은 가장 빈번하게 사용 될 입출력이기에, 이를 비동기화 하는 것은 매우 중요했다. 다만, 각 운영체제마다 제공하는 비동기 네트워크 입출력 모델이 다른 점이 번거로운데, 이는 boost::ASIO를 사용하여 손쉽게 해결할 수 있었다.

비동기 데이터 베이스 요청 처리 및 캐싱

데이터베이스로 요청을 보내고, 응답을 받기까지의 대기 또한 성능에 병목을 발생시킬 수 있는 요소 중 하나이다. 이를 피하기 위해 데이터베이스와 게임 서버 사이에 DB Cache Server를 두었다. DB Cache Server는 게임 데이터를 캐싱하고, 데이터베이스 입출력 요청을 처리하는 역할을 담당한다. 모든 데이터베이스 요청 처리는 DB Cache Server로 위임함으로써, 게임서버에서는 해당 처리가 완료될때까지 봉쇄되지 않고 다른 작업을 수행할 수 있다.

비동기 로그 처리

게임 진행과 함께 다양한 정보를 파일 또는 터미널으로 출력하게 되는데, 이 때 발생하는 디스크 입출력 또한 큰 병목이 될 수 있는 부분이다. 이를 비동기적으로 처리하기 위해, 파일/터미널 입출력을 전담하는 스레드를 두어 처리하도록 LogSystem을 설계하였다. 더불어, 파일/터미널 입출력 순서를 의미 단위(하나의 로그 요청 단위)로 정렬하여 출력함으로써, 멀티 스레드 환경에서도 의도된 의미대로 출력되는 로그 시스템을 만들 수 있다.

여기까지 크루세이더스 듀얼의 게임서버가 높은 성능을 가질 수 있도록 설계시 고민하고 시도한 내용이다. 다음 편에서는 안정성을 확보하기 위해서 시도한 것들을 이야기하고, 'GameTask 처리'를 예로 들어 이야기 해 보려 한다.
